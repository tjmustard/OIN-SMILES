residuals the generated structure re-encodes byte-identically to the *mirrored* input, so the

## The finding that reframes the release

`docs/RENUMBERING_INSTABILITY_v0.4.5.md`. On a 225-molecule seed-42 sample (223 encoded, 2
trials/transform, levers OFF):

| | count | share |
|---|---:|---:|
| byte-stable | 125/223 | 56.1% |
| drifted | 98/223 | 43.9% |
| **comparison KEY changed** | 47/223 | **21.1%** |
| **absolute stereochemistry changed** | 29/223 | **13.0%** |

`rotate` produced **zero** drift across the whole sample — the encoder is fully
orientation-invariant. Every defect is an **atom-numbering** dependence.

The 13% is a **soundness** defect: the strings are byte-identical once `@`/`@@` are deleted, so
the neighbour ordering is the same and the tags denote genuinely different configurations — at
least one of each pair is wrong. Verified by hand on `FEQFIS_comp_0` (identical sorted
coordinate multiset, a pure permutation).

**Consequence: "100% round-trip accuracy" is not currently well-defined**, because round-trip
success is partly a property of the input file's atom order. Determinism is a precondition for
measuring it.

### 🔴 RETRACTED — the boron "permanent ceiling" was not permanent, and I was wrong about why

`swimlane/v045-boron`, 8 commits, `docs/BORON_CAGE_v0.4.5.md`. **48/48 round-trip OK behind
`OIN_BORON_CAGE`** (default OFF).

I documented 34 molecules as permanently unfixable because "RDKit's 2c-2e valence model has no
Lewis structure for a 3c-2e cage." That reasoning was **about a stage the code never reaches.**

The real obstacle is a valence *rule* in **adjacency** perception, two stages earlier.
`xyz2AC_obabel` builds the AC from a covalent-radius criterion — which perceives the cages
**exactly**, hitting textbook edge counts (o-carborane 10 B / 21 edges, closo-B₁₂ 12/30,
dicarbollide 9/18) — and then runs a loop deleting an atom's longest bonds while its degree
exceeds `max(atomic_valence[Z])`. **`atomic_valence[5] == [3, 4]`, but a deltahedral vertex has
5–6 neighbours.** Measured across 34/34: the loop deletes **406 of 993 B–B bonds (40.9%) at
1.712–2.105 Å** — the textbook carborane B–B range. Real bonds, not marginal contacts.

Failure site is **degenerate, 34/34**: amputation → `GetMolFrags` shatters the cage into sub-cages
plus loose `[H]B` → `get_lig_mol` fails on the debris → `OINEncodeError`. **`AC2BO`, `SanitizeMol`
and `MolToSmiles` are never reached** — so the model-level argument I made was never in play.

Representations tried: **single bonds + `SANITIZE_ALL ^ SANITIZE_PROPERTIES` works** (sanitizes,
serializes, re-parses graph-identical, canonical SMILES idempotent). `DATIVE` fails — it counts
toward the end atom's explicit valence. `ZERO`/`UNSPECIFIED` encodes but **does not round-trip**:
30 uniform ZERO bonds return as 19 SINGLE + 11 UNSPECIFIED.

#### And the finding that matters more: 14 molecules are scored as PASSES while describing the wrong graph

The A/B over 120 passing molecules found one difference, `VEJXOZ` — **not a regression, an extra
defect.** With the lever off it loses 6 of 12 cage bonds and the encoder **invents a C=B double
bond** to balance valences. It emits an OIN. It round-trips. **It is wrong** — and
`canonical_roundtrip_key` cannot see it, because the corrupted encode is compared against its own
corrupted mol. **That is the lossy-key trap again**, in a new place.

Corpus scan: **186 molecules carry a cage and all 186 have bonds deleted.** 34 fail loudly, **14
fail silently while being scored correct** (losing 49.4% of cage bonds), and 138 were never
measured by the capstone arm at all.

⇒ **The accuracy metric has been counting wrong answers as passes.** The true baseline is *lower*
than measured, at the same time as the ceiling is *higher*.

#### Two latent crashes found in passing

- **A cage chiral tag is a native heap corruption, not an exception.** RDKit tags a 6-connected
  cage vertex, then `FindPotentialStereo` dies in `basic_string::_M_create` / `free(): invalid
  pointer` → SIGABRT/SIGSEGV — **on the second encode in a process**, so a single-molecule test
  passes and a *sweep* dies later, unattributably. The tag that aborted was on a thiaborane's
  **cage sulfur**, not boron, so the guard covers the whole deltahedron.
- **`AC2BO` calls a bare `sys.exit()`** when `possible_valence` is empty — an uncatchable process
  kill for any over-coordinated element. That is why the fix bypasses `AC2BO` rather than widening
  the valence table.

#### Why it is not promoted

For the 34 it cannot regress anything. But for the **14 it changes a scored-passing OIN** — a real
behaviour change on the headline metric, even though the new answer is the correct one. Gated on a
strict **B–B–B triangle** motif (borates, boroxines, diboranes and linear B–B–B chains all
excluded); lever OFF is **120/120 byte-identical to the frozen capstone OIN**; goldens 6/6
byte-identical both arms; `test_boron_cage` 19/19.

**Sharper verdict, replacing mine:** the obstacle was `atomic_valence[5]` topping out at 4 inside a
bond-pruning loop. What remains is a **convention** question, not a representational one — a
single-bonded cage graph is not a Lewis structure, and its formal charge (currently 0, the
neutral-cage reading) is a decision nobody has made, which changes the metal token. Neither blocks
a canonical lossless 1D hash.

### Perf lane: a 48–57 s call was running twice per rejected conformer

`swimlane/v045-perf` @ `c89f0bf7`. **This is the first change this release that attacks the
*dominant* accuracy lever** — `hard_fail` is 92% of the closeable gap and roughly half of it is
timeout-shaped, so generator cost *is* accuracy.

`metallogen_adapter._reencode_key_matches`'s confirming step (`_reencode_oin`, a full
`XYZToSMILES().convert()` re-perception of a freshly embedded conformer) was measured at
**48–57 s per call** and ran **twice per rejected conformer**: once inside `generate_3d_structures`'s
pool-fill `accept_fn` (SL1 early-exit, default-ON since v0.4.4), then redundantly again inside
`_select_by_geometry_impl`'s own early-exit re-scan over the same returned pool. Anything reaching
the second site had already been tested when `accept_fn` accepted it — a match there short-circuits
the whole pool via `return [early_hit]` — so the second call recomputes a known answer.

Fixed with a per-`generate()` cache keyed on `id(mol)`, defaulting to `None` everywhere so any
caller that does not opt in is byte-identical. A cache hit can only return what a fresh call already
returned, so this is **pure dead-work removal** — the same class as the existing PuLP topology memo
and `embed.py`'s `alt_cache` — and it lands **ungated** per this release's own rule for provably
byte-identical work.

| | measured |
|---|---|
| byte-identity | **SHA-256 of generated XYZ identical** across cisplatin, transplatin, ferrocene, POJJOP, QIDKUL_comp_0 (git-show A/B) |
| `reencode_oin_full_calls` | **4 → 2** — exact halving, a deterministic counter |
| `generate_s` on QIDKUL_comp_0 | 212.8 s → 116.0 s (**~1.8×**) — *same contended session; not a clean-host number* |
| suite / ruff | 605 green / clean |

### Encoder perf: `AC2BO` is 99.8% of a slow encode — and it is NOT an eta phenomenon

`swimlane/v045-encspeed`, 4 commits. Nobody had ever profiled the encoder. The answer is one

|---|---|---|

| `ResonanceMolSupplier` | **0 calls** | **0 calls** |

so the affected population is a different, and currently unmeasured, set.

Mechanism: `_select_lig_mol` is a charge/carbene ladder calling `AC2BO` up to **5× on the same
adjacency matrix**. These ligands exceed `_VALENCE_COMBO_CAP`, so each arm grinds all

arm — 55.6% of matchings measured redundant.

(dropped a per-carbon `list(BO[i,:]).count(1)` allocation, inlined `get_atomic_charge`, unboxed

| counter | before | after |
|---|---:|---:|
| `nx.max_weight_matching` calls | 60,001 | **26,668** |
| `get_atomic_charge` calls | 4,440,174 | **132** |
| `charge_is_OK` inclusive | 14.35 s | **3.59 s** |

Interleaved paired A/B with arms alternating so contention averages: **1.62× eta, 2.16× non-eta.**

A/B). Suite 605 OK + 8 new guards.

**Three negative results worth keeping:** numpy-vectorizing the small per-atom loops is *slower* at

would have buried them in load noise.

**A product question this raises:** for these ligands perception **fails** — no valid Lewis structure
among 20,000 candidates — and `best_BO` is a fallback. **The search is spending ~15 s per ladder arm
to buy a guess.** Worth asking whether it should give up sooner.

#### I tested the lane's own follow-up hypothesis, and my first test was broken

The lane flagged the highest-value untested question: is a *generated* conformer's ligand AC
byte-identical to the input's? If so, every SL1 accept-first re-encode becomes a memo hit.

My first test said **0/36 identical, 44–168 bond differences** — which should have been an
immediate tell, because 44+ differing bonds on a 60-atom molecule would make it unrecognizable.
The test was **order-sensitive** and the generator writes atoms in a different order. Redone
order-insensitively (bond element-pair multiset + (element, degree) multiset):

| | result |
|---|---|
| atom **symbol sequence** identical | **0/36 (0%)** |
| **graph** fingerprint identical | **16/36 (44%)** |

So: the graph *is* preserved 44% of the time, but the atom **order never is** — meaning the memo as
built **cannot hit on the generated side**, because its key is a permutation away. Capturing that 44%
needs an *order-invariant* memo key. That is the concrete follow-up.

Second finding from the same test, unrelated to perf: **56% of generated structures do not preserve
the input's graph** even up to isomorphism. That is a large number and it bears on the `structural`
bucket.

#### The 30 s target after this work

`QIDKUL_comp_0` encode is now ~25 s at load 12, ~15 s warm — but a round trip runs **at least two**
encodes, so ~40 s of encode alone before generation starts. The remaining charge-*dependent* half
(`BO_is_OK` + `charge_is_OK` + `get_BO` over 60,000 candidates, ~13–15 s) is **not memoizable**,
because it is precisely the part that differs per ladder arm. That is the floor for ligands over
`_VALENCE_COMBO_CAP`.

The two levers that would close it both **change perceived bond orders**, so neither is
byte-identical and neither was attempted: lowering `_VALENCE_FALLBACK_TRIES` (`best_BO` depends on
which candidates were tried), and replacing `nx.max_weight_matching` — the graph carries no weights,
so this is really maximum *cardinality* matching, and a faster algorithm exists but may return a
different equally-large matching. Both need a lever plus a corpus A/B.

### ✅ RESOLVED — the "7 wrong-donor molecules" were NOT a defect. See below.

**Lane 9 refuted this section.** Read `docs/WRONG_DONOR_v0.4.5.md` on `swimlane/v045-lane9`

For **all seven**, the two competing strings place donors on template vertices related by a
**proper rotation of the coordination polyhedron**, so neither is wrong about which atom is bound
where. Tally: `identity 4 / in_rotation_group 4 / NOT_A_ROTATION 0`. `|Δrssd|` across all 8 pairs is
`0.0 … 1.2e-14` — *exactly* tied. Donor count equals vertex count for all seven, so the permutation
constrains every vertex and the group test is exact rather than permissive. `canonical_roundtrip_key`
agrees: `key_equal = True` for 14/14 variants. **Lane 9 shipped no encoder change**, because a fix
would have frozen one of two equally faithful labelings.

`_map_to_template`'s Kabsch fit is degenerate over the proper-rotation group *by construction* —
`template[p∘g] == R_g · template[p]`, so both labelings are the same optimization with an identical
residual. The fit determines donor→vertex only *up to* the group; which tied member wins is settled
by the strict `<` keeping the lex-first candidate, i.e. by atom order.

**Why the classifier said `DISTINCT_donors`:** it asks a per-fragment, positionally-zipped question
about a **global** relabeling. `RUBTIS`'s chelate donors genuinely are inequivalent, but the full
relabeling is `(0 1)(2 3) ∈ D₄` because the COD arms swapped too. Plus two mechanical bugs (`zip`
assumed a stable fragment order, which the post-pass derives *from* slots; haptic donors were keyed
on the marker's first occurrence). Renamed `distinct_donors_LOCAL` with a warning.

**And a sub-mechanism nobody predicted:** for 4 of the 7 the Kabsch fit **did not move at all**
(π = identity). The drift enters *downstream* — `_permute_and_serialize`'s lex-max over the same
group, its homogeneous-sort rank assignment, and which of two equivalent donors the body renders
first (the `CanonicalRankAtoms(breakTies=True)` tie). **So a fix aimed only at the Kabsch tie-break
would close at most 3 of the 7.** The real defect behind all 30 residuals is one thing: *the choice
among group-related labelings is settled on atom order, in three separate places.*

Chemistry footnote: in `VEXHIR`/`KISQAG` (acac), `IMACOO` (β-diketiminate) and `HAVGIW` (dipyrrin)
the donors are "inequivalent" **only in the localized Kekulé form** — they are resonance pairs, and
chemically equivalent.

**This unblocks a decision.** One of Lane 2's three reasons for declining its own §7a wider fold was
"it would over-fold your 7" — **refuted**: all seven are already related by a proper rotation, which

geometry's own symmetry, and it needs a Δ/Λ guard.

  widening the fold is broader, riskier, and buys nothing. Note a fix aimed at the Kabsch tie alone
  closes **at most 3 of 7** — for 4 of them the fit never moved.

Trading a real over-folding risk for zero headline gain is a bad trade. Recorded as declined, with
the invariance work named as the alternative for v0.4.6.

### A sixth instrument defect — and this one was self-caught by arithmetic

The boron lane's suite reported `Ran 623 tests, OK`. It **did not accept the green result**: it
checked the count and found 623 is one short of the 624 the loader collects. Cause — it had edited
`tests/unit/test_boron_cage.py` **while that suite run was in flight in the same worktree**, and
`discover` imports at collection time, so the run covered 605 pre-existing tests plus 18 of what
are now 19 boron tests: a count matching neither the old tree nor the new one.

**Generalizable rule, and it applies to every lane here:** do not edit a test file while a suite
run is in flight in the same worktree. The discrepancy is a single digit and would be rounded away
by anyone reading the summary line.

What makes this worth recording is not the miscount — it is that the failure mode produced a
**green** result. A red suite gets investigated; an `OK` with a slightly wrong denominator gets
quoted. The lane separated what the evidence supported (605 pre-existing tests genuinely ran and
passed on the final `src`; explicit collection gives 624 with 605 non-boron and 0 load failures, so
nothing was dropped or silently unimportable; the 19 boron tests pass directly) from what it did
not (a single clean invocation over all 624), rather than rounding.

## The valence-search floor: reducible ~100×, and the search saturates at 0.5% of its budget

`swimlane/v045-valsearch`, 6 commits, `docs/VALENCE_SEARCH_v0.4.5.md`. Both levers default OFF.

**How often does the search actually fail?** Answered *without running it* — over-cap is decidable
from the adjacency matrix, so the scan costs ~0.04 s/molecule instead of ~50 s:

| sample | molecules | over-cap |
|---|---:|---:|
| random, seed 1 | 100 | **0 (0.0%)** |
| random, seed 7 | 1,992 | **4 (0.2%)** |
| slow / failing cohort | 313 | **4 (1.3%)** |

**The rate is not the finding — the enrichment is.** Those 4 are `KESWUB`, `BENVOG`, `HICLAG`,
`HOHKUL`: **4 of the 7** molecules the encode_fail triage lists as unresolved encoder-side cost.
Rare corpus-wide, but the majority of the encoder's known residue.

**Does the answer depend on the budget?** It saturates at ~100 candidates out of 20,000:

| tries | 1–25 | 50 | **100** | 200 → 20,000 |
|---|---|---|---|---|
| `BO.sum()` | 92 | 94 | 94 | 94 |
| BO sha | `5320…` | `facb…` | **`9d23…`** | `9d23…` stable |

So my framing — "the search grinds 20,000 candidates to buy a guess" — was **half right and the
wrong half mattered**: it is genuinely useful for the first ~100 and useless for the remaining
19,900. Below 25 candidates the answer is *worse*; at 50 it has the right sum with the wrong matrix.

Whole-encode effect, with the 20,000 arm repeated as a self-check and both OIN SHAs matching
`encspeed`'s independently recorded values: **`QIDKUL` 148.10 s → 0.92 s, `QIDKIZ` 631.88 s →
2.50 s, identical `best_BO` and identical OIN.**

**The matcher was a wrong premise — clean negative.** Production graphs are **14–17 nodes**, so the
cost was *call count* (60,001), not complexity. `maxcardinality=True` is **5.3× slower** for an
identical answer; `nx.maximal_matching` is 17× faster but maximal-not-maximum and returns a
different `best_BO`. After the budget cut the matcher runs ~600× instead of ~60,001×, so **the cut
takes the same seconds without touching a single bond order — it strictly dominates.** Nothing
should ship behind a matcher lever.

**The over-cap class splits three ways** — which the sibling lane could not see, having measured one
ligand:

| ligand size | behaviour |
|---|---|
| ~37 atoms | floor collapses ~15 s/arm → ~0.3 s/arm, OIN byte-identical |
| 92–147 atoms | `HICLAG`, `LIYFAA` **time out at 20,000 and complete at 200** — 2 encode failures become encodes |
| 148–220 atoms | `KESWUB`/`BENVOG`/`HOHKUL`/`ZAZREZ` time out at **both**. `HICLAG` spent 145.74 s on 401 candidates = 0.36 s each, ~70× the small ligand — **per-candidate cost binds, not count** |

### The lead it deliberately did not chase, and it is an accuracy lead

The over-cap branch does not merely cap the search — it also **skips `_ordered_valences`** and
iterates the unsorted product. Sub-cap ligands succeed in **3–8 candidates** *because* of that
ordering heuristic; over-cap ones fail in 20,000 *without* it.

⇒ **`found_valid = 0` may be a statement about search ORDER, not about the ligand.** Applying the
heuristic to a bounded prefix could turn a fallback guess into a real Lewis structure. That would be
a **correctness** win, not a speed one, and it reframes "perception fails for these ligands" as
possibly an artifact of how the candidates are enumerated.

### Caveats it raised rather than let pass

- **The 2 molecules the cut rescues are exactly the 2 whose fidelity cannot be verified** — the
  20,000 baseline never produces a string to compare against. SHAs recorded for a quiet host.
- **`encspeed`'s "two molecules" are one 37-atom ligand measured twice**, so its profile was less
  general than it read.
- **`XIRMER` is sub-cap yet ran >35 min** — a slow encode is *not* evidence of an over-cap ligand.
- It found and fixed two bugs in its own harness: `$?` read after a pipeline (which would have
  hidden **every** timeout) and a denominator silently shrinking 2,000 → 1,992.
- It did **not** run its own pre-change baseline, because a second 2,256 s run would have taken
  cores the headline sweep needs — so that comparison is arithmetic, not a paired run, and it says so.

Promotion to a 200-candidate budget is **recommended, not taken**: 0 changed OIN strings across the
14 molecules where both arms completed, and 99.8% of the corpus is unchanged *by construction*
(the lever is read only inside `if over_cap:`).

## DECISION: promote `OIN_BORON_CAGE`. Correctness beats the metric.

I said this trade was a product call. On reflection it is not — it is a technical call with an
unambiguous answer, and treating it as a judgement call was me hiding behind the metric.

**The trade as stated:** the lever fixes 48 molecules, but 14 of them *currently count as passes*,
so promoting makes the headline number go **down**.

**Why that is the wrong way to read it.** Those 14 do not pass in any meaningful sense. `VEJXOZ`
loses half its cage bonds and the encoder **invents a C=B double bond** to balance valences. It then
round-trips — against its own corrupted mol. The pass is an artifact of comparing a wrong answer to
itself, which is the lossy-key trap this entire release has been documenting. Corpus-wide, **186
molecules carry a cage and all 186 have bonds deleted**; 34 fail loudly, 14 fail silently while
scored correct, 138 were never measured.

This project's stated purpose is a **canonical lossless 1D hash** of a transition-metal complex. An
encoder that knowingly emits a graph with 40.9% of a cage's real bonds deleted, and a fabricated
double bond, is not lossless. Holding the lever off to protect a percentage would mean **choosing to
ship a wrong answer because the wrong answer scores better** — precisely the failure this release
found six instruments committing.

**So: promote it, and report the corrected baseline.** The number going down is the *measurement
getting more honest*, not the encoder getting worse. Any accuracy figure quoted from here on should
be quoted against the corrected baseline, and the 14 should be named so the drop is not mistaken for
a regression.

**What stays open, and is genuinely a product call:** the cage's **formal charge** is currently 0
(the neutral-cage reading), which makes the derived metal oxidation state not what a chemist would
write for a dicarbollide. That changes the metal token, so it is a notation convention someone has
to choose — and unlike the promotion, no measurement settles it.

### And `OIN_H_FAITHFUL` stays OFF — for a reason, not for want of a decision

Not deferred: **blocked, with a known cause.** `canonical_body_emit` (now default-ON) reparses the
body through `MolFromSmiles`/`MolToSmiles`, which is exactly the round trip that re-reads a bare 0-H
symbol one hydrogen heavier — the defect `OIN_H_FAITHFUL` exists to prevent. Promoting it now would
have one default-ON lever silently undo another. The fix is to make `canonical_body_emit` H-faithful
or to reorder the two; until then, off is correct. Recorded in `oin/levers.py::_HELD_OFF` and at the
call site.

## The valence-order spike: my hypothesis refuted, and a bigger defect found underneath

`swimlane/v045-valorder`, 5 commits, `docs/VALENCE_ORDER_v0.4.5.md`. Both levers default OFF.

**My hypothesis was wrong.** `found_valid = 0` is **not** an ordering artefact. And the mechanism I
proposed — "sort each atom's list, then `itertools.product`" — is a **near-no-op**, because
`atomic_valence` is *already* preferred-first (`C [4,2]`, `N [3,4]`, `O [2,1,3]`), so raw `product`
already yields the all-preferred candidate first. The lane implemented the exact lazy heuristic order
anyway, measured it, and it is **worse**: `_ordered_valences` varies **O slowest**, and O/N are
precisely the atoms that must change — `HICLAG`'s first feasible candidate moves from rank **4 →
32,768**. For three molecules the two orders are *literally the same sequence*, so the hypothesis was
vacuous there.

**What actually broke it open.** `AC2BO`'s acceptance predicate has a necessary condition that is
**additive over atoms**: a valid return forces `BO.sum(axis=1) == valences` exactly, so
`charge_is_OK` reduces to a per-atom function of the candidate. A **suffix DP** therefore *counts*
the feasible set of the entire space and yields the exact **rank** of the first feasible candidate in
any order — closed form, **8.4 s of CPU for all 8 molecules** instead of 50 s encodes each.

| molecule | lig atoms | space | feasible | valid exists? | first index: raw / heuristic / **filter** |
|---|---:|---:|---:|---|---|
| `QIDKUL` | 37 | 1,259,712 | **16** | **yes** (rank 629,761) | none in 20k / none / **10** |
| `QIDKIZ` | 37 | 1,259,712 | **16** | **yes** | none / none / **10** |
| `LIYFAA` | 92 | 1,679,616 | **0** | **NO — provably, at any budget or order** | — |
| `HICLAG` | 147 | 53,747,712 | 97,868 | yes | timeout / timeout / **1,129** |
| `BENVOG` | 148 | 26,873,856 | 74,108 | yes | 15 / 225 / **1** |
| `ZAZREZ` | 144 | 8,503,056 | 1,424,304 | yes | 649 / 649 / **1** |
| `KESWUB` | 188 | 6,718,464 | 41,020 | yes | timeout / timeout / **1,216** |
| `HOHKUL` | 220 | 26,873,856 | 74,108 | budget exhausted (583 s) | — |

### The OIN change is a losslessness fix, not a cosmetic one

`QIDKUL`/`QIDKIZ` are Rh(COD)Cl and AuCl **NHC** complexes. The default emits the carbene as an
aromatic imidazolium — and **that string does not re-read**: `KekulizeException`, only **3 of 4
fragments parse** (`QIDKIZ` 2 of 3). The filter emits the neutral carbene and **4 of 4 fragments
re-parse**. Mechanism isolated: the guess is a charge-separated ylide (`[c-]`/`[n+]`) that kekulizes
*with* its charges, and emission drops them.

⇒ **The encoder was emitting strings that cannot be parsed back.** That is a direct losslessness
failure, in the one place this project's purpose lives. `found_valid` goes 0 → 3 over-cap calls;
charges sum to target, no hypervalent atoms, `SanitizeMol` OK, and 124.44 s → **0.87 s** as a
side effect.

**Sub-cap byte-identity 16/16** — 12 scan-confirmed sub-cap dataset molecules plus all four goldens,
OIN identical, candidate counts identical, `over_cap_calls = 0` everywhere. The levers are read only
inside `if over_cap:`, so 99.8% of the corpus is untouched by construction.

**The design is strictly dominant, and both properties were tested:** the filter is a *subsequence*
of the raw product in the same relative order, so the first valid candidate it finds is the one an
unbounded raw search would find (confirmed — `BENVOG`/`ZAZREZ` return identical `best_BO`); and when
the feasible set is **empty** it falls back to the historical enumeration, so it can never turn one
guess into a *different* guess (`LIYFAA`). It also found by inspection that all 30 transition metals
have an `atomic_valence` entry but **no** `atomic_valence_electrons` entry, so the DP would `KeyError`
before candidate 1 — `charge_filter_supported()` declines those fragments.

### ⚠ Two corrections to things I relayed

1. **I repeated that "below 25 candidates the answer is genuinely worse, sum 92". That is inverted.**
   The sum-92 matrix is precisely the **validated** Lewis structure; the sum-94 matrix the full
   20,000-candidate search returns is the **unvalidated guess**. **`BO.sum()` is not a quality
   metric** and I used it as one.
2. **The ligand-size split does not survive.** `KESWUB` (188 atoms) is rescued, `BENVOG` (148) was
   never failing, and the 37-atom pair is the *hardest* by feasible density. Per-candidate cost is
   **0.012–0.027 s, not 0.36 s** — that figure divided whole-encode wall clock by candidate count.

### The next defect, named by this lane and unexplored

`KESWUB`/`HOHKUL` have huge feasible sets whose **first member is at rank 14** — so the default path
*does* examine plausible candidates and still fails. That points at **`get_BO`'s greedy iterated
matching failing to saturate them**, not at the enumeration. And `LIYFAA`'s provable zero-feasible
result relocates that molecule to the **charge proposal**: the DP makes "is this charge even
reachable?" a millisecond gate the charge ladder does not currently have.
