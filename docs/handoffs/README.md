# Round-Trip Fix Wave — Parallel Session Protocol

Six independent sessions (S1–S6), each in its own git worktree, each owning a
disjoint set of files. Every session fixes one defect class found in the
tmCAT/tmPHOTO round-trip baseline (`tmCAT-tmPHOTO_xyz_dataset/20260707-results/`).

**Read your own `S*.md` handoff, then this protocol. Do not touch files another
session owns** (each handoff lists them).

## Where the truth lives

- `tmCAT-tmPHOTO_xyz_dataset/20260707-results/CASE_REGISTRY.md` — molecule →
  defect class → owning session, regenerated by `tools/classify_failures.py`.
  Rows marked `pre-provenance` may be stale (produced by older code); rows with
  a `commit_id` are attributable. A Phase-0 bulk re-run refreshes everything;
  if `PHASE0_DONE` exists in the results dir, the registry is current.
- Every handoff pre-seeds verified example molecules so you can start before
  Phase 0 finishes.

## Worktree setup

```bash
cd /home/tjmustard/Documents/GitHub/OIN-SMILES

git worktree add ../OIN-SMILES-<slug> -b feature/roundtrip-<slug> main
cd ../OIN-SMILES-<slug>

```

## Reproducing a case

The dataset lives only in the main checkout (it is gitignored). From your
worktree:

```bash
uv run python tools/test_dataset_roundtrip.py \
    --dataset-dir ../OIN-SMILES/tmCAT-tmPHOTO_xyz_dataset \
    --output-dir /tmp/rt-<slug> \
    --quick --only <MOLECULE>[,<MOLECULE>...]
```

**Never point `--output-dir` at the shared `20260707-results/`** — a continuous
runner and possibly Phase-0 workers write there live. Use a private scratch dir.

The report JSON in `<output-dir>/individual_reports/<MOL>.json` carries
`smiles_1` (input encode), `smiles_2` (re-encode of generated 3D), the error,
and provenance (`commit_id`, `rdkit_version`).

## Acceptance criteria (every session)

1. Your target molecules round-trip: canonical keys match (and RMSD/atom-count
   pass where your class affects them).
2. New unit guard tests for the fix (see each handoff).
3. Full suite green: `uv run python -m unittest discover tests/unit`
   — baseline 233 OK / 4 skipped; your tests add to that. No new failures.
4. Regression spot-check: re-run the named currently-passing molecules in your
   handoff and confirm they still pass.

## Landing

- Squash-PR to `main` (project convention; PR #2/#3 precedent). Do not merge
  granular branch history by hand.
- When another session's PR lands mid-flight, **rebase your branch onto the new
  main** before opening yours.
- Put the before/after evidence (molecule list, key match, RMSD) in the PR body.

## Environment gotchas

- `uv sync` in a fresh worktree installs **rdkit 2026.3.3**; the long-running
  baseline venv (`~/.venv`) is **2025.09.3**. Both are blessed; the golden-env
  guard test accepts the set. To cross-check on the older version:
  `uv pip install rdkit==2025.9.3 && uv run --no-sync ...`.
- No `xtb` binary on this machine → g-xTB tiers silently run the FF fallback.
  This wave is FF-only by decision; do not chase optimizer-level RMSD noise.
- `ruff --fix` on D-rules can truncate docstrings — re-read files after autofix
  (bit us at 033f1c5). The pre-commit hook enforces `ruff format`.
- The metal is ALWAYS `fragments[0]` in an OIN (load-bearing invariant).
- MetalloGen's geometry key `8_squre_antiprismatic` is misspelled upstream —
  do not "correct" it (broke once already).
- Use mean RMSD, never max-per-atom, for any metric threshold.
- The η³-allyl saga's lesson: two prior handoffs asserted plausible-but-wrong
  root causes. Treat your handoff's hypothesis as a hypothesis; run the
  verify-first steps before writing code.
