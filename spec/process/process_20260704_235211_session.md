## Patterns & Lessons

- **Verify PRD claims against source before red-teaming them.** Reading every cited `file:line` in the target document (not just the prose) turned up findings the draft author had genuinely missed (e.g., F1/F2's silent-failure surfaces) and let the report separate "confirmed facts" from "hazards," making the subsequent `/hyper-resolve` triage sharper.
- **A concurrently running GUI git client (GitHub Desktop) can auto-stash the entire working tree on a branch switch without restoring it — indistinguishable at first glance from catastrophic data loss.** Always check `git reflog` + `git stash list` before concluding files are gone, and never run destructive recovery without user confirmation on shared VCS state.
- **`python` is not guaranteed on PATH in `uv`-managed projects** — scripts invoked directly (as opposed to via `uv run`) can fail silently in ways that are easy to misattribute to something else going wrong.
- **When splitting a mixed working tree across branches, trace imports rather than guessing from filenames.** The decisive signal for the MetalloGen/round-trip split was `grep`-ing for who imports/consumes each ambiguous file (`metallogen_adapter.py`'s imports, `OINVector.slot`'s readers), not file location or diff size.
- **Check what a pre-commit hook actually scopes over before assuming `--no-verify` is unavoidable or safe.** Here the hook ran whole-tree lint; scoping a manual check to just the files being committed showed they were already clean, which both justified the narrow `--no-verify` use and confirmed `main` would be green again once the unrelated experimental tree left it.
