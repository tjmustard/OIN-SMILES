## What the "999" actually is (measured)

`rmsd_utils.calculate_tmc_rmsd` now returns **distinct** sentinels (user edit 2026-07-05):
`999`=no metal, `998`=empty sphere, `997`=element-key-set mismatch, `996`=per-element count
mismatch (prints `[RMSD DEBUG]`), `995`=exception, `994/993/992/991`=permutation-RMSD branches.

**TiCat1 → 997 (element-key mismatch). Strings byte-IDENTICAL.** Measured spheres:
```
INPUT  (distance-based, use_bonds=False): {Ti:1, C:12, Si:1}
GEN    (bond-based,      use_bonds=True ): {Ti:1, C:12}          # Ti bonded to 12 C only
```
The lone difference is the **bridging ansa-Si**. TiCat1 is a silyl-bridged bis-Cp
(`C[Si](C)(Cp)(Cp)TiMe2`); the Si sits geometrically near Ti but does **not** coordinate it
(there is no Ti–Si bond). So:
- INPUT `_extract_coordination_sphere(use_bonds=False)` counts Si as a donor by **distance**
  → false positive.
- GEN `_extract_coordination_sphere(use_bonds=True)` uses the contract mol's real Ti bonds
  (12 C, no Si) → chemically correct.
- Element-key sets `{Ti,C,Si}` ≠ `{Ti,C}` → return 997. The **geometry is fine; the RMSD
  simply can't be computed** because the two extraction modes disagree on what "coordinates."

TiCat3/TiCat4 are indenyl analogues that ALSO have the `C[Si](C)(...)` bridge and byte-identical
strings → almost certainly the same 997 (confirm per below). TiCat2 additionally has a **string
mismatch** (separate issue, see §"TiCat2 extra"). TiCp2Me2 is a **different** failure (RMSD 1.45,
a real rotamer phase — leave it; format-inherent).

## Sub-issue A (primary, test-harness): reconcile the two coord-sphere definitions

`_extract_coordination_sphere` in `tests/integration/rmsd_utils.py` extracts differently for the
two operands: input by **distance**, generated by **bonds**. For eta/ansa systems these disagree
(distance drags in the non-bonded bridging Si). Fix so both operands use a **consistent** donor
definition. Options (pick one, keep it principled):
1. **Distance-mode: exclude non-donor bridge atoms.** After the distance cut, drop atoms that
   are not plausibly bonded to the metal (e.g. Si/second-sphere main-group atoms beyond a tighter
   element-aware cutoff, or atoms with no metal bond when bond info exists). Least invasive.
2. **Use bond-based for BOTH operands** when both mols carry bonds (the input `tmc_mol` from
   `get_tmc_mol` does have perceived metal bonds). Most consistent; verify it doesn't change the
   currently-passing complexes' RMSD.
3. **Intersect the spheres** on the common donor set before comparison (compute RMSD over atoms
   present in both), logging any dropped atoms so silent truncation is visible.
Recommendation: try (1) first (smallest blast radius), fall back to (2). This is a **test-only**
change (`rmsd_utils.py`) — it does not touch the OIN string, which already round-trips correctly.

**Guard:** re-run the FULL suite after — this file computes RMSD for ALL 25 complexes, so a
definition change must not regress the 19 passers (especially the other eta cases Ferrocene,
TiCp2Me2, Zeise's, and CO/hydride complexes). Ferrocene passes today (RMSD 0.013) — keep it.

## Sub-issue B (encoder, small): TiCat2 kekulized Cp

TiCat2 round-trips with a **string mismatch** (the ONE residual string bug):
```
OIN(1): ...c{1}1[cH]{1}[cH]{1}[cH]{1}[cH]{1}1...   (aromatic Cp)
OIN(2): ...C{1}1[CH]{1}=[CH]{1}[CH]{1}=[CH]{1}1... (kekulized — C=C, uppercase)
```
The generated contract mol's eta Cp ring is emitted **Kekulé/aliphatic** instead of aromatic.
`build_contract_mol` (`src/oinsmiles/generation/metallogen_adapter.py`) transfers template
aromaticity (`SetIsAromatic` on atoms) but the lenient perception (`GetSymmSSSR` only, no full
sanitize) can leave the RING BONDS non-aromatic for this case. Note TiCat1/3/4 come out aromatic
(strings identical), so it is case-specific — diff TiCat2's contract-mol Cp bond types vs TiCat1's.
Fix: force AROMATIC bond type on eta rings whose atoms are aromatic-flagged in
`build_contract_mol` (mirror the guard at `oin_aligner.py:50-58`, which only rescues SINGLE bonds
— TiCat2's may be DOUBLE from the `Kekulize` in `convert_parsed_to_msmiles`). **But note:** even
with B fixed, TiCat2 stays FAIL until A is fixed (it is also 99x-blocked). Do A first.
